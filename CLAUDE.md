# ERP-CRM
React + TS + Vite client / Node + Express + TS server. sql.js (SQLite in-memory + file persist). JWT auth.

## Structure
- `server/src/` — index.ts, database.ts, routes/, middleware/, lib/, types/
- `client/src/` — App.tsx, main.tsx, pages/, components/, contexts/, lib/
- `server/uploads/` — invoices, wire-transfers, orders, operation-docs
- `server/data/` — SQLite file persistence

## Commands
- Dev server: `npm run dev:server` (tsx watch)
- Dev client: `npm run dev:client` (vite)
- Build: `npm run build` (client vite build + server install)
- Start: `npm run start`

## Key Modules
- `server/src/database.ts` — sql.js wrapper; `db.prepare(...).run/get/all()` (better-sqlite3-like API)
- `server/src/lib/fx.ts` — Frankfurter API FX rates, in-memory cache per process
- `client/src/lib/api.ts` — axios, base `/api`
- `client/src/lib/dates.ts` — `formatDate()` returns DD/MM/YYYY (EU format)

## Patterns
- Auth: JWT via `req.user.userId`; `authenticateToken` re-reads the user row each request (deleted user → 401, role from DB, not the token)
- Migrations: try/catch `ALTER TABLE` at bottom of `initializeDatabase()`
- Currency: store `amount` + `currency` + `fx_rate` + `eur_amount`; aggregate via `COALESCE(eur_amount, amount)`; display EUR throughout
- Theme: Zoho-CRM style tokens (primary blue, slate greys, radii, Lato) in `client/src/index.css` `@theme` — restyle there, don't move controls
- Dates: use `formatDate()` from `client/src/lib/dates.ts` (DD/MM/YYYY); "today" is `todayISO()` (client `lib/dates.ts` = the user's local day, server `lib/today.ts` = Brussels) — never `new Date().toISOString().slice(0, 10)` (UTC, yesterday until 01:00/02:00)
- Async route handlers: a throw/rejection goes to the error handler (`lib/asyncErrors.ts` patches Express 4, imported first in `index.ts`) — without it one bad request crashed the whole server
- Operation statuses: pre-ordered, ordered, in production, shipped, in clearance, delivered, completed (`VALID_STATUSES` in `routes/operations.ts`, same lists on the Operations, operation and New Operation pages)

## Security
- No public sign-up: accounts come from admin create or invite only; login is password + emailed OTP (5 wrong codes burn it; 10 wrong per user in 30 min locks the code step; compare dates with `datetime(expires_at)`). `/login` returns a 15-min signed `challenge` (`generateOtpChallenge`, purpose 'otp' — never accepted as a session); `/verify-otp` and `/resend-otp` require it, so the code step can't be reached without the password
- A first admin is seeded only when there are no users (random password in the log) — never re-created
- `uncaughtException` / `unhandledRejection` are logged, not fatal (`lib/asyncErrors.ts`); binding an object/array to SQL → 400; sort / paging query values are allowlisted (`Object.hasOwn`) or clamped
- `server/package.json` `overrides.qs` pins the patched qs under Express 4
- 401 means "session gone" (client logs out) — use 400 for a wrong password/code inside a valid session
- Any file name taken from a request must match `^[a-zA-Z0-9._-]+$` before it is stored, served or unlinked
- `/api/files` renders only PDF/images inline; other types download. CSP set in `index.ts` helmet — new external hosts must be added there
- User-entered text in email HTML goes through an escape helper
- Update endpoints: a field left out keeps its stored value, a field sent blank clears it

## Archive (deleted files)
- A file a user deletes or replaces is never unlinked: `lib/archive.ts` `archiveStored(subfolder, storedName, meta, by?)` / `archiveFile(abs, …)` / `archiveBuffer(buf, …)` (supplier invoices' embedded PDFs) move it to `uploads/archive` and add an `archived_files` row (`section`, `context` e.g. "SOBE20260125 — Bill of Lading", `file_name`, `stored_name`, `size`, `reason` deleted | replaced, `deleted_by_*`, `deleted_at`); `archivedBy(req)`, else the request user from `requestUser` (AsyncLocalStorage set in `authenticateToken`); `ownerOf(operationId, ncoId)` / `contextOf(...)` build the labels. Never throws (falls back to removing the file)
- Covered: operation / NCO documents (delete, replaced file, Word text edit), operation / order / invoice / supplier deletes, generated OC / PO / invoice / PL / declaration / COA PDFs, wire transfers, payments, library + batch documents, supplier documents, TripleW bank documents, employee expenses, supplier invoices (single, batch, month replace). NOT archived: refused uploads, a ZIP after unpacking, regenerated PDFs (the old generated version), DB / template files
- New delete code must archive the same way. Page `/archive` (`pages/ArchivePage.tsx`, sidebar "Archive"): search, section filter, preview / download (`/api/files/archive/`), admin "Delete for good" (`DELETE /api/archive/:id`); `GET /api/archive?search=&section=&page=` returns `sections` counts

## Settings page

## Wire Transfers
- `POST /invoices/:id/wire-transfers` — upload + mark invoice paid; fetches FX on upload date, stores `fx_rate` + `eur_amount`
- `DELETE /invoices/:id/wire-transfers/:transferId` — reverts invoice to `sent`
- No approval workflow; no confirmation modals (inline drag-drop IS the confirm)
- Payment received email (`lib/paymentEmail.ts`): every wire transfer uploaded on a CUSTOMER invoice emails the recipients chosen in User Management → Payments (`components/PaymentRecipients.tsx`, admin; `app_settings.payment_notifications` = `{recipients: ['user:<id>' | 'email:<addr>']}`, `GET/PUT /api/settings/payment-notifications`, `POST …/test` sends a sample; deleted users dropped). Bold, cheerful "Hip hip hooray — we got paid!" (random headline + sign-off), customer / invoice / operation / amount + EUR / date / bank ref / who recorded it, wire PDF attached (≤ 10 MB), link to the operation (`APP_URL`). Sent after the response (`void`), never throws, never blocks the upload

## Product Documents (Inventory → Documents)
- Library of MSDS / Product Specification Sheets / Declarations / COAs: `product_documents` (`kind` 'msds' | 'pds' | 'declaration' | 'coa', `title`, `doc_code` e.g. HSE-00-REP-004, `sha256`), files in `uploads/product-docs` (PDF, images, .doc/.docx), `/api/product-documents`, `components/ProductDocumentsTab.tsx` (Inventory `?tab=documents`, one sub-tab per kind)
- A document covers any number of products (`product_document_products`); none = general (all products). Deleting a product deletes only the documents that were its alone
- Import ZIP (`POST /import` `{file, kind}`, `lib/productLibrary.ts`): code + title read off `"<CODE> - <title>.ext"`; products from `DOC_PRODUCTS` (read off the documents — each MSDS lists its trade names), else a spec sheet's title, else catalogue names in the title, else general. Matching: same name, else same brand + Midas-ness + code token (`findCatalogueProduct`); missing ones are created (Circulac / Naturlac by name, SKU blank). Re-import: same code + title (else file name) → unchanged skipped, changed replaced; links only ever added
- `products.sku` is optional (blank = NULL; Products tab shows "SKU missing")
- Inventory → Products → Import SKUs (`components/SkuImportModal.tsx`, `lib/skuImport.ts`): `POST /api/products/import-skus` (.xlsx) reads every "commercial name | reference" pair (references like LACLA80 / VBNV100; packaging codes and "… PU25" variants ignored; "Obsolete" sheets skipped), matches the catalogue by name (spacing / hyphens ignored, else brand + grade code + other words) → preview set / change / same / not_found / conflict; `POST /api/products/skus {updates}` saves the ticked ones (a code moving between products is applied in passes). Never creates products
- Operation → Documents → Add from library (`components/AddFromLibraryModal.tsx`): four sections (MSDS, Product Specification Sheet, Declarations, COA; COAs ticked when they name one of the operation's lots — `/suggest` returns `coa_lot_matches` — else the best per product), each listing the whole category (searchable) with the suggestions ticked on top, so any other document can be chosen instead; `GET /suggest?operation_id=` reads the lines of the operation's generated invoice (final over draft), else its order lines; `matchProduct` (longest name / SKU as whole words, `lib/productDocs.ts`); ticks per product the most specific MSDS and spec sheet (fewest products, then highest doc code) and every linked declaration; general documents listed unticked. `POST /copy` files a COPY under the operation (category MSDS / Product Specification Sheet / Declaration) — later library changes never touch it

## Declarations (generator)
- Per operation or NCO, any number: table `declarations` (`operation_id` | `nco_id`, `status` draft|final, `data` JSON, `draft_data`, `source`, `document_id` | `nco_document_id`; `GET /by-operation/:id`, `/by-nco/:id`), `/api/declarations`, page `pages/DeclarationPage.tsx` (`/declarations/new?operation_id=` → pick a start: library declarations (operation's products suggested), ones generated on other operations, upload .docx/.pdf, or blank; `/declarations/:id` → form + live preview, Save draft / Confirm & generate / regenerate like the PO)
- Starting documents are read by `lib/declarationSource.ts`: Word header → title / department; body paragraphs (bold → `**…**`, list items → `• ` / `  – `), tables; "issued in X on DATE (by)" → place / date (ISO), then signatory / role; the body image → signature in `uploads/declaration-assets` (served `/api/files/declaration-assets/`); PDFs give text paragraphs only. The last used signature is the default
- PDF `lib/declarationPdf.ts` (TripleW layout: logo, green title, department, optional "To" addressee, heading, paragraphs / bullets / tables, "issued in … on August 5th, 2026 by", signature, name, role; long tables tighter so it stays one page); filed under the operation as category Declaration, `<op#> - <title>.pdf`, replaced in place on regenerate; deleting that operation document deletes the declaration
- Shipping documents Declaration tile: lists the operation's declarations (draft / edits pending) + other filed declarations, "Generate" / "Add declaration" opens the generator
- COA uses the same generator: `declarations.kind` 'declaration' | 'coa' (`/declarations/new?…&kind=coa`, `kind` on `/sources`, POST, preview); starts: library COAs (suggested when title / code / notes / file name names one of the owner's lots — `coaMatchesLots` — else by product), batch COAs (`source_type: 'batch'`, the lots' suggested), earlier COAs, upload (saved to the library as kind coa), or a blank COA (`emptyCoa`: per product a Product / Batch / Production / Expiry table from `ownerProductLots`, a Parameter / Specification / Method / Result table, conformity line); filed as category COA, "This certificate was issued…". The COA tile lists the generated COAs, keeps Choose (file an existing COA as is) and Generate / Add COA
- Uploaded declarations (generator upload, or any upload filed as Declaration on an operation) are also saved to the library (`saveDeclarationToLibrary` in `lib/documentSources.ts`, kept once by sha256, linked to the operation's products, notes "Uploaded on <op#>")

## Non-Commercial Operations
- Own page `/non-commercial-operations` (sidebar "Non-Commercial Ops"), table `non_commercial_operations`, `/api/non-commercial-operations` — separate from `operations`, so never in revenue / dashboard / analytics / working capital

Documents already generated keep their number
- List: search box (number, customer / from → to, notes, type, status, date) and every column sortable (client-side, blanks last, choice in localStorage `nco.sort`, default date newest first) on top of the entity / type / status filters
- New NCO window: "New client" adds a customer inline (`POST /api/customers`) and selects it
- Status (`non_commercial_operations.status`, default 'requested'): requested / samples_in_preparation / samples_available / shipment_in_preparation / shipped / delivered / cancelled (`NCO_STATUSES` server route + `client/src/lib/ncoStatus.ts`); set in the New/Edit window, changed inline from the list's Status column or the NCO page header (`components/NcoStatusSelect.tsx`, `PUT {status}`); list filter `?status=`; changes are in the notification detail

- Detail page `/non-commercial-operations/:id` (`pages/NcoDetailPage.tsx`; a row click / a new NCO opens it): lines (`non_commercial_operations.items` JSON — product, reference, packaging (`packaging_id` + `packaging` name, from Inventory → Packaging: rows whose product list names the line's product are listed first under "Made for …" and the best one is picked when a catalogue product is chosen and none is set; any other packaging selectable; printed in the NCO documents' Packaging column, the sample invoice falls back to "Sample bottle"), quantity, unit, unit value, currency, lots, HS code), documents (`nco_documents`, files in `uploads/operation-docs`, uploads with a category e.g. Invoice), Send documents

- Full check (Summary → Full check, `InvoiceFullCheck.tsx`, `lib/invoiceCheck.ts`): ONE run (`POST /full-check/run` → `check_runs`) that the server moves on by itself: `text` (free: PDF text extracted → `invoice_triage`, `invoice_texts`; never marks an invoice correct on its own) → `ai_pdf` (Sonnet batch reads EVERY PDF once, ~$0.007 each; cached, so re-checks only read new / changed files) → `done` | `stopped` (reason in `message`).
